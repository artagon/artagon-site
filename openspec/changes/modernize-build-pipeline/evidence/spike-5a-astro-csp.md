# Spike 5A — Astro-native CSP parity

**Recommendation: reject a direct replacement; revisit after the gaps below have explicit implementations and tests.** Astro's generated policy does not cover every inline script in the current build. Replacing `scripts/csp.mjs` as-is would also lose its post-write audit and HTML-symlink rejection. Browser enforcement and a deployment header were not tested.

## Method and environment

On 2026-11-02, copied the tracked project into a disposable directory under the system temporary directory, created a local Git fixture, and symlinked the existing dependency tree. Used Node `v26.13.0` and installed Astro `7.4.5`; no dependencies were installed. An ordinary lifecycle build produced the comparison tree. In the disposable copy only, changed `astro.config.ts` to enable `security.csp` with SHA-256, script resources `['self']`, style resources `['self', https://fonts.googleapis.com, { resource: "'unsafe-inline'", kind: 'attribute' }]`, and explicit `default-src`, `img-src`, `font-src`, `connect-src`, `object-src`, and `base-uri` matching the current script. The first attempt to put `style-src-attr` in `directives` failed config validation; the scoped resource succeeded. Ran `npx --no-install astro build` without the existing CSP postbuild gate, saved the output, then ran `node scripts/sri.mjs` and saved that output too.

Astro documents SHA-256 as the default, scoped resources and directives, and limits for external resources; these are configuration capabilities, not a promise of this site's parity. Sources: [Astro configuration reference](https://docs.astro.build/en/reference/configuration-reference/#securitycsp), [Astro CSP source documentation](https://github.com/withastro/docs/blob/main/src/content/docs/en/reference/configuration-reference.mdx). Context7 returned current docs for `/withastro/docs`; the installed version was checked separately.

## Results

- **23/23 matching HTML routes** had exactly one policy in each tree. After explicit configuration, each had the same non-hash values for all nine checked directives: `default-src`, `img-src`, `style-src`, `style-src-attr`, `font-src`, `connect-src`, `object-src`, `base-uri`, and `script-src`.
- An independent Cheerio parse recomputed SHA-256 over each inline script and style body and compared each to its route's directive. The existing postbuild tree covered **158/158 script occurrences and 17/17 style occurrences**. The native tree covered **27/158 scripts and 17/17 styles**. Of 131 missing script occurrences, 85 were `application/ld+json` data blocks and **46 were classic scripts without a type**; 25 module scripts were covered. Counts are occurrences across routes, not unique hashes. This fails the current all-inline-script contract; native browser enforcement was not exercised.
- `node scripts/sri.mjs` exited 0 on the native build (`files=23 entries=9`): 33 generated integrity attributes appeared, and the independent hash coverage counts were unchanged before versus after SRI. Native CSP alone emitted zero integrity attributes. This check does not prove future downstream mutation safety.
- In a disposable negative control, wrapped the existing `processHtml` write so a script changed after serialization; the existing post-write audit rejected the orphan hash. The shared HTML walker rejected a symlinked HTML file. Separately, Astro's native build accepted a symlinked public HTML input and copied the external fixture bytes as a regular output file. The focused existing SRI outside-dist asset-symlink regression passed (1 passed, 21 intentionally skipped). Native CSP did not demonstrate equivalent post-write or symlink protection.
- Neither present build produced `_headers`. The Cloudflare proposal calls for a future `csp.mjs`-generated per-site header alongside the meta policies; it is not implemented today. Native metadata output alone does not prove or implement that future union/header contract.

The disposable comparison script parsed `<meta http-equiv>` case-insensitively, split directives on semicolons, and compared each computed `'sha256-…'` to `script-src` or `style-src`. Scratch scripts and raw build outputs remained outside the worktree. No production code or configuration was edited.

## Immutability guard

Before and after the experiments, on the production worktree, the task's `git diff --exit-code`, `git diff --cached --exit-code`, and empty `git status --porcelain=v1 --untracked-files=all` across its declared guarded roots all passed (exit 0). The exact combined task guard was exercised in a separate disposable Git fixture: a staged file in `scripts/` made it exit 1; after unstaging, the same untracked file made it exit 1; after removing that fixture, it exited 0. `vitest run tests/lint-scoped-package-versions.test.mts` exited 0.
