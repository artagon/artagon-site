## MODIFIED Requirements

### Requirement: Lighthouse CI Ready Signal

The system SHALL configure Lighthouse CI collection in `lighthouserc.json` using `ci.collect.staticDistDir` set to `.build/dist` (sourced from `build.config.json` via `scripts/sync-build-config.mjs`) and path-only route entries in `ci.collect.url` (sourced from `scripts/fixtures/lhci-assertions.json`), and MUST NOT combine `staticDistDir` with `startServerCommand`. During `lhci collect` or `lhci autorun`, `@lhci/cli` (`@lhci/cli@0.15.x`) SHALL serve `.build/dist/` over HTTP via its built-in static file server (`FallbackServer` in `node_modules/@lhci/cli/src/collect/fallback-server.js:27-61`). `scripts/lhci-serve.mjs` MAY remain as an optional standalone local server helper that emits `READY` once `http://localhost:8081/` responds, but `lighthouserc.json` and `.github/workflows/lighthouse.yml` SHALL NOT invoke it, and `README.md` SHALL document `staticDistDir` as the active collection mode. Lighthouse CI report output MUST be written to `.build/reports/lhci/`, sourced from `build.config.json` via `scripts/sync-build-config.mjs`. `lighthouserc.json` is a generated file. CLI-managed runtime state remains in the ignored `.lighthouseci/` directory; it is not wired to `BUILD.cache` or restored by CI.

This Requirement governs ONLY paths and the static-server collection contract. Assertion shape (URL/category gates, severity) is governed by a future `Lighthouse CI Performance Gate` Requirement under the `style-system` capability — that requirement is currently in the unarchived `update-site-marketing-redesign` change and will be cross-referenced here once it archives. Until then, the marketing-route assertion contract remains in `lighthouserc.json` directly via the `lhci-assertions.json` fixture consumed by the sync script.

#### Scenario: LHCI starts audits from staticDistDir after build

- **GIVEN** `npm run build` has populated `.build/dist/` and `lighthouserc.json` is generated from `build.config.json`
- **WHEN** `npx --no-install lhci collect --config=lighthouserc.json && npx --no-install lhci upload --config=lighthouserc.json` (or `npx --no-install lhci autorun --config=lighthouserc.json --fail-on-upload-failure`) runs
- **THEN** `@lhci/cli` serves `.build/dist/` via `ci.collect.staticDistDir` without invoking `scripts/lhci-serve.mjs` or `startServerCommand`, audits every route in `ci.collect.url`, uploads HTML/JSON reports and `manifest.json` to `.build/reports/lhci/`, and exits non-zero if `.build/dist/` is absent or if filesystem upload fails.

#### Scenario: LHCI collect URLs resolve to built static HTML routes and serve HTTP 200 via FallbackServer

- **GIVEN** `.build/dist/` exists after `npm run build` and `lighthouserc.json` defines `ci.collect.staticDistDir` and `ci.collect.url`
- **WHEN** `tests/lint-lhci-trailing-slash.test.mts` validates `lighthouserc.json`, `README.md`, `.build/dist/`, and `@lhci/cli`'s `FallbackServer` (`node_modules/@lhci/cli/src/collect/fallback-server.js:27-61`)
- **THEN** `ci.collect.staticDistDir` equals `BUILD.dist`, `ci.collect.startServerCommand` is undefined, `README.md` documents `staticDistDir` rather than claiming `lighthouserc.json` invokes `scripts/lhci-serve.mjs`, every route in `ci.collect.url` maps to an existing HTML file under `.build/dist/` (`index.html` for `/`, `<route>/index.html` or `<route>.html` for non-root routes), and `FallbackServer` serves HTTP `200` with non-empty HTML for all 6 routes and HTTP `404` for an unknown route.

#### Scenario: Lighthouse reports under .build/reports

- **GIVEN** `.build/dist/` has been built, `.build/reports/lhci/` is clean, and `lighthouserc.json` sets `ci.upload.target` to `filesystem` and `ci.upload.outputDir` to `.build/reports/lhci`
- **WHEN** Lighthouse CI collection and filesystem upload (`lhci collect` + `lhci upload`, or `lhci autorun --fail-on-upload-failure`) complete successfully
- **THEN** fresh HTML and JSON report files and `manifest.json` covering all 6 routes in `ci.collect.url` are written to `.build/reports/lhci/` (`node_modules/@lhci/cli/src/upload/upload.js:535,572-578`), while raw CLI runtime state remains in `.lighthouseci/` (`node_modules/@lhci/utils/src/saved-reports.js:10,50-55`).

#### Scenario: Lighthouse drift fails CI

- **GIVEN** `lighthouserc.json` is generated by `scripts/sync-build-config.mjs` with a `$sha` provenance header
- **WHEN** a contributor edits `lighthouserc.json` directly without running `sync:build-config`
- **THEN** CI's drift gate fails with "build config drift" before Lighthouse executes.

### Requirement: Playwright tests produce structured reports

Playwright tests MUST emit per-test results to `.build/reports/playwright/results/` and HTML reports to `.build/reports/playwright/html/`. CI shards MUST also emit blob reports to `.build/reports/playwright/blob/` for merging. These paths MUST be sourced from `build.config.ts` via `BUILD` in `playwright.config.ts`; no string literals duplicating these paths may appear in that config. No Playwright cache path is wired. In `.github/workflows/playwright.yml`, the 5 `test` shards, `visual-regression`, and `accessibility` jobs MUST consume the `.build/dist/` artifact produced by the same-run `build` job after verifying `${BUILD.reports.buildProvenance}/provenance.json` (`.build/reports/build-provenance/provenance.json`) via `node scripts/verify-build-provenance.mjs --verify` with `EXPECTED_PRODUCER_RUN_ATTEMPT: ${{ needs.build.outputs.producer-run-attempt }}` and `EXPECTED_MANIFEST_SHA256: ${{ needs.build.outputs.manifest-sha256 }}`, while preserving all 13 required check names (`docs/build-artifacts.md:118`, including `test (1)` through `test (5)`, `visual-regression`, `accessibility`, and `merge-reports`). The required `merge-reports` job MUST declare `needs: [build, test, visual-regression, accessibility]` and `if: ${{ always() }}`, merge and upload shard blob reports (`retention-days: 14`) with the lockfile-pinned CLI into `BUILD.reports.playwright.html` whenever `build` succeeded and `test` was not skipped, and enforce an event-aware expected-job policy in an always-run final step: `needs.build.result`, `needs.test.result`, and `needs.accessibility.result` MUST equal `'success'` on all events; `needs.visual-regression.result` MUST equal `'success'` on `pull_request` and `push` (`github.event_name != 'workflow_dispatch'`) and MAY equal `'skipped'` only when `github.event_name == 'workflow_dispatch'` (matching `.github/workflows/playwright.yml:221`, while trusted-`main` `update-snapshots` at `.github/workflows/playwright.yml:275` remains independent); and any other skip, failure, or cancellation MUST exit `1`.

#### Scenario: Playwright reports under .build/reports

- **GIVEN** `playwright.config.ts` imports `BUILD` from `build.config.ts`
- **WHEN** Playwright tests run (passing or failing)
- **THEN** the per-test artifacts are at `.build/reports/playwright/results/`; the HTML report is at `.build/reports/playwright/html/`; no output appears at the legacy `test-results/` or `playwright-report/` paths.

#### Scenario: Playwright CI jobs verify same-run build artifact before running browsers

- **GIVEN** the `build` job in `.github/workflows/playwright.yml` has built `.build/dist/`, written `.build/reports/build-provenance/provenance.json`, and uploaded the artifact with `outputs.artifact-id`, `outputs.producer-run-attempt`, and `outputs.manifest-sha256`
- **WHEN** any `test` shard, `visual-regression`, or `accessibility` job starts after `needs: [build]`
- **THEN** it downloads the build artifact by `needs.build.outputs.artifact-id`, verifies `.build/reports/build-provenance/provenance.json` against the runner's `GITHUB_SHA`, `GITHUB_RUN_ID`, `EXPECTED_PRODUCER_RUN_ATTEMPT`, `EXPECTED_MANIFEST_SHA256`, `process.version`, input config digests (`package-lock.json`, `build.config.json`, `astro.config.ts`), and `.build/dist/` file hashes, and preserves all required status check names.

#### Scenario: Partial rerun of a failed browser job verifies against producer attempt output

- **GIVEN** `build` succeeded on attempt `1` (`needs.build.outputs.producer-run-attempt == '1'`) and its 1-day artifact has not expired, and an operator triggers "Re-run failed jobs" for a failed shard or browser job on attempt `2` (`GITHUB_RUN_ATTEMPT == '2'`)
- **WHEN** the retried job downloads `needs.build.outputs.artifact-id` and runs `node scripts/verify-build-provenance.mjs --verify` with `EXPECTED_PRODUCER_RUN_ATTEMPT=1`
- **THEN** provenance verification succeeds because `manifest.producerRunAttempt` equals `EXPECTED_PRODUCER_RUN_ATTEMPT` (`"1"`), whereas if the 1-day artifact has expired or `manifest.producerRunAttempt` mismatches `EXPECTED_PRODUCER_RUN_ATTEMPT`, the job fails closed before running Playwright and requires "Re-run all jobs".

#### Scenario: Producer failure or cancellation fails required merge-reports check

- **GIVEN** the `build` job in `.github/workflows/playwright.yml` fails, fails to upload its artifact, or is cancelled (or `visual-regression` is skipped on a `pull_request` or `push`), causing downstream browser jobs to be skipped
- **WHEN** `merge-reports` executes with `if: ${{ always() }}` and `needs: [build, test, visual-regression, accessibility]`
- **THEN** `merge-reports` runs its final `if: ${{ always() }}` enforcement step and exits `1` (`conclusion: failure`) because the event-aware expected-job policy is not satisfied, ensuring branch protection blocks the PR.

#### Scenario: Manual workflow_dispatch run succeeds when visual-regression is intentionally skipped

- **GIVEN** `.github/workflows/playwright.yml` is triggered by `workflow_dispatch` (on trusted `refs/heads/main` where `update-snapshots` builds independently, or on another ref) and `visual-regression` is skipped by `if: github.event_name != 'workflow_dispatch'`
- **WHEN** `merge-reports` executes with `if: ${{ always() }}` and `needs: [build, test, visual-regression, accessibility]`
- **THEN** `merge-reports` exits `0` when `build`, `test`, and `accessibility` all equal `'success'` and `visual-regression` equals `'skipped'`, and exits `1` if `build`, `test`, or `accessibility` is `'failure'`, `'cancelled'`, or `'skipped'` or if `visual-regression` is `'failure'` or `'cancelled'`.
