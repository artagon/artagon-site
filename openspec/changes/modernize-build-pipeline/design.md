## Decisions

### D1: Standardize Lighthouse CI on `ci.collect.staticDistDir` and verify HTTP static serving

Keep `staticDistDir: buildConfig.dist` (`".build/dist"`) in `scripts/sync-build-config.mjs:161` and `lighthouserc.json:6` as the canonical LHCI collection mode, and amend `Requirement: Lighthouse CI Ready Signal` in `openspec/specs/check-site-quality/spec.md:11-30`.

- **Why:** `@lhci/cli@0.15.1` (`package.json:100`) natively serves static build directories via `FallbackServer` (`node_modules/@lhci/cli/src/collect/collect.js:186-222`, `node_modules/@lhci/cli/src/collect/fallback-server.js:27-61`), awaits `server.listen()` on an ephemeral port (`collect.js:188`), logs `Started a web server on port ${server.port}...` (`collect.js:189`), and resolves path-only URLs (`["/", "/platform", "/roadmap", "/vision", "/security", "/faq"]` in `lighthouserc.json:7-14`). Upstream Lighthouse CI documentation forbids combining `staticDistDir` with `startServerCommand`. Furthermore, `scripts/lhci-serve.mjs:24` invokes `npx http-server`, and `http-server` is not declared in `package.json:83-111`, so wiring `lhci-serve.mjs` into CI would introduce an unpinned network package fetch or fail under `--no-install`.
- **Two-tier verification gate:**
  1. `tests/lint-lhci-trailing-slash.test.mts` asserts `ci.collect.staticDistDir === BUILD.dist`, `ci.collect.startServerCommand === undefined`, `README.md` prose accuracy (documenting `staticDistDir` and not claiming `lighthouserc.json` starts `scripts/lhci-serve.mjs`), fails closed if `.build/dist/` is missing, verifies every URL in `ci.collect.url` maps to a built HTML file, and instantiates `@lhci/cli`'s `FallbackServer` (`node_modules/@lhci/cli/src/collect/fallback-server.js:27-61`) against `.build/dist/` to prove all 6 configured routes return HTTP `200` while an unknown route returns `404`.
  2. Real CLI execution (`npx --no-install lhci collect --config=lighthouserc.json && npx --no-install lhci upload --config=lighthouserc.json`, or `npx --no-install lhci autorun --config=lighthouserc.json --fail-on-upload-failure`) against a clean `BUILD.reports.lhci` (`.build/reports/lhci`) directory verifies both collection (`node_modules/@lhci/cli/src/collect/collect.js:137` → `.lighthouseci/` via `node_modules/@lhci/utils/src/saved-reports.js:10,50-55`) and filesystem upload (`node_modules/@lhci/cli/src/upload/upload.js:535,572-578`, since `lhci autorun` at `node_modules/@lhci/cli/src/autorun/autorun.js:145-147` only warns on upload failure unless `failOnUploadFailure` is set), asserting newly written HTML/JSON reports and `.build/reports/lhci/manifest.json` for all 6 routes plus negative controls for missing `.build/dist/` (collect startup failure) and collect-without-upload / upload failure.
- **Alternatives considered:**
  - *Switch `scripts/sync-build-config.mjs` to emit `startServerCommand: "node scripts/lhci-serve.mjs"` and `startServerReadyPattern: "READY"`:* Rejected because it adds a hardcoded port (`8081` at `scripts/lhci-serve.mjs:13`) that can collide locally and requires either adding `http-server` to `devDependencies` or rewriting `scripts/lhci-serve.mjs` around `node:http` static file serving with zero functional gain over `@lhci/cli`'s built-in static server.
  - *Delete `scripts/lhci-serve.mjs` immediately:* Rejected in this step because `README.md:210,690-691` documents it for manual local debugging; instead, `README.md` is updated to document `staticDistDir` as what `lighthouserc.json` uses and mark `scripts/lhci-serve.mjs` as a standalone manual helper.

### D2: Document `.astro/` as a named CLI-managed exception in `build-config`

Amend `Requirement: .build/ Umbrella Layout` in `openspec/specs/build-config/spec.md:13-39` and `docs/build-artifacts.md:7,15-22,67,102` to include `.astro/` alongside `.lighthouseci/` and `.lycheecache` as a named CLI-managed exception.

- **Why:** In `astro@7.4.5` (`package.json:89`), `astro.config.ts:14` sets `cacheDir: BUILD.cache.astro` (`.build/cache/astro`), which relocates the production build cache and production content-layer data store (`node_modules/astro/dist/content/paths.js:7-9`: `getDataStoreFile` selects `settings.dotAstroDir` when `isDev` is true and `settings.config.cacheDir` otherwise). However, `createBaseSettings` in `node_modules/astro/dist/core/config/settings.js:16-17` hardcodes `const dotAstroDir = new URL(".astro/", config.root);` for generated TypeScript declarations (`.astro/types.d.ts`, `.astro/content.d.ts`), CLI preferences (`.astro/settings.json`), and `astro dev` data-store output. Because `dotAstroDir` is not configurable in Astro 7.4.5 without changing `root`, `.gitignore:26` already ignores `.astro/` in place. Naming it in `build-config` aligns the spec with Astro 7's actual behavior.
- **Alternatives considered:**
  - *Set `root` in `astro.config.ts` or symlink `.astro/` into `.build/cache/astro`:* Rejected — changing `root` shifts Astro's default resolution of `srcDir` (`./src`), `publicDir` (`./public`), `outDir` (`./dist`), and `cacheDir` (`./node_modules/.astro`) in `node_modules/astro/dist/core/config/schemas/relative.js:18-24` and `node_modules/astro/dist/core/config/schemas/defaults.js:2-7` (while `node_modules/astro/dist/core/config/settings.js:138` still resolves `./package.json` from `cwd`), and symlinking `.astro/` breaks fresh checkouts before `.build/` exists and violates repository symlink hygiene.
- **Cross-change prerequisite with `standardize-repository-layout`:** Currently `.lycheecache` is tracked in Git (`git ls-files -- .astro .lighthouseci .lycheecache` prints `.lycheecache`). `openspec/changes/standardize-repository-layout/tasks.md:18,21` (PR 1 ordering note at line 18 and Task `1.2` / unit `LAYOUT-01B` at line 21) untracks `.lycheecache` (`git rm --cached .lycheecache`). Therefore, `standardize-repository-layout` PR 1 MUST land before (or in the same commit as) `modernize-build-pipeline` PR 1 Task `1.4`.

### D3: Same-run Playwright build-artifact reuse, `BUILD.reports.buildProvenance` SSoT path, partial-rerun binding, and fail-closed `merge-reports`

Add a dedicated read-only `build` job to `.github/workflows/playwright.yml` and have `test` (5 shards), `visual-regression`, and `accessibility` depend on `needs: [build]` and download the built `.build/dist/` artifact by `artifact-ids: ${{ needs.build.outputs.artifact-id }}`.

- **Why:** Building once per workflow run eliminates 6 redundant initial executions of `astro build` + the 12-stage `postbuild` chain in `.github/workflows/playwright.yml` while keeping every shard and browser job in the exact same pinned container (`mcr.microsoft.com/playwright:v1.59.1-jammy@sha256:8a0360d39d1973be506dd59002904a774f6d697d4946c94063b3fd006461c8ff`, `.github/workflows/playwright.yml:66,225,360`).
- **SSoT Provenance Path (`BUILD.reports.buildProvenance`):**
  - To satisfy `Requirement: .build/ Umbrella Layout` (`openspec/specs/build-config/spec.md:15-20`) and `Requirement: Single Source of Truth Path Config` (`openspec/specs/build-config/spec.md:40-48`), add `"buildProvenance": ".build/reports/build-provenance"` under `reports` in `build.config.json:6-15`, `BuildPaths.reports` (`build.config.ts:12-17`), and `REQUIRED_SHAPE.reports` (`build.config.ts:71-76`), and run `npm run sync:build-config` to update the `$sha` / `sha=` banners in `lighthouserc.json` and `lychee.toml`.
  - `scripts/verify-build-provenance.mjs` imports `BUILD` from `../build.config.ts` and writes `${BUILD.reports.buildProvenance}/provenance.json` (`.build/reports/build-provenance/provenance.json`). Storing the manifest under `.build/reports/build-provenance/` keeps `.build/dist/` free of non-deployed files (preserving `sri-manifest.json` and Cloudflare purge URL lists in `tests/ci-workflow-behavior.test.mts:296-333`) and ensures `npm run clean:reports` cleans it up.
- **Provenance fields and explicit producer-attempt binding for partial reruns ("Re-run failed jobs"):**
  - `scripts/verify-build-provenance.mjs --write` writes `{ sha, runId, producerRunAttempt, nodeVersion, inputDigests: { "package-lock.json": "<sha256>", "build.config.json": "<sha256>", "astro.config.ts": "<sha256>" }, distFiles: { "<rel-path>": "<sha256>", ... } }` to `.build/reports/build-provenance/provenance.json` and outputs `producer-run-attempt=${process.env.GITHUB_RUN_ATTEMPT}` and `manifest-sha256=<sha256>` to `$GITHUB_OUTPUT`.
  - The `build` job uploads `.build/dist/` and `.build/reports/build-provenance/provenance.json` in a single artifact (`playwright-dist-${{ github.run_id }}-${{ github.run_attempt }}`, `retention-days: 1`, `include-hidden-files: true`, `if-no-files-found: error`) via `actions/upload-artifact@043fb46d1a93c77aae656e7c1c64a875d1fc6a0a` (`v7.0.1`) and declares job outputs:
    - `artifact-id: ${{ steps.upload-dist.outputs.artifact-id }}`
    - `producer-run-attempt: ${{ steps.provenance.outputs.producer-run-attempt }}`
    - `manifest-sha256: ${{ steps.provenance.outputs.manifest-sha256 }}`
  - Consumer jobs (`test`, `visual-regression`, `accessibility`) download via `actions/download-artifact@3e5f45b2cfb9172054b4087a40e8e0b5a5461e7c` (`v8.0.1`) with `artifact-ids: ${{ needs.build.outputs.artifact-id }}` and `path: .build` (single-artifact download extracts directly into `.build/dist/` and `.build/reports/build-provenance/provenance.json`), then run `node scripts/verify-build-provenance.mjs --verify` with `EXPECTED_PRODUCER_RUN_ATTEMPT: ${{ needs.build.outputs.producer-run-attempt }}` and `EXPECTED_MANIFEST_SHA256: ${{ needs.build.outputs.manifest-sha256 }}`.
  - `--verify` checks and fails closed (`exit 1`) on any mismatch in:
    1. `manifest.sha === process.env.GITHUB_SHA`
    2. `manifest.runId === process.env.GITHUB_RUN_ID`
    3. `manifest.producerRunAttempt === process.env.EXPECTED_PRODUCER_RUN_ATTEMPT` (binds to the `build` producer job's attempt output rather than the retrying consumer's `process.env.GITHUB_RUN_ATTEMPT`, so "Re-run failed jobs" on consumer attempt 2+ succeeds against a valid attempt-1 producer artifact while a mismatched producer attempt fails)
    4. SHA-256 of `.build/reports/build-provenance/provenance.json` === `process.env.EXPECTED_MANIFEST_SHA256`
    5. `manifest.nodeVersion === process.version`
    6. SHA-256 digests of `package-lock.json`, `build.config.json`, and `astro.config.ts` === `manifest.inputDigests`
    7. Exact 1:1 file set and SHA-256 digests of `.build/dist/` === `manifest.distFiles` (rejecting any missing, modified, or extra file).
  - **Expired-artifact recovery (`retention-days: 1`):** If a failed job is retried after the 1-day artifact retention window expires, `actions/download-artifact` fails closed before tests run; the documented recovery procedure in `docs/agents/testing.md` and `docs/build-artifacts.md` is **Re-run all jobs** so `build` regenerates the artifact.
- **Event-aware fail-closed required status check enforcement via `merge-reports`:**
  - All 13 required status check names (`docs/build-artifacts.md:118`, `tests/branch-protection-workflows.test.mts:247-279`) remain unchanged.
  - Because GitHub branch protection treats `skipped` required jobs as passing when an upstream `needs:` dependency fails, is cancelled, or is skipped, `.github/workflows/playwright.yml:171-218` updates `merge-reports` (one of the 13 required checks) to:
    - Declare `needs: [build, test, visual-regression, accessibility]` and `if: ${{ always() }}`.
    - Guard the report download/merge/upload steps with `if: ${{ !cancelled() && needs.build.result == 'success' && needs.test.result != 'skipped' }}` so shard blob reports are still merged and uploaded whenever `test` shards ran (including on test failures).
    - Run a final step `Enforce upstream build and browser job success` with `if: ${{ always() }}` (after report upload) that inspects `github.event_name`, `needs.build.result`, `needs.test.result`, `needs.visual-regression.result`, and `needs.accessibility.result` (passed via `env:`) and enforces an **event-aware expected-job policy**:
      1. `needs.build.result === 'success'`, `needs.test.result === 'success'`, and `needs.accessibility.result === 'success'` are required on **every** trigger event (`pull_request`, `push`, and `workflow_dispatch`).
      2. When `github.event_name != 'workflow_dispatch'` (`pull_request` or `push`), `needs.visual-regression.result === 'success'` is also required.
      3. When `github.event_name == 'workflow_dispatch'`, `visual-regression` is intentionally skipped by its job-level `if: github.event_name != 'workflow_dispatch'` guard (`.github/workflows/playwright.yml:221`, while trusted-`main` snapshot updates run in the independent `update-snapshots` job at `.github/workflows/playwright.yml:275`), so `needs.visual-regression.result` MAY equal `'skipped'` (or `'success'`) on `workflow_dispatch`, whereas `'failure'` or `'cancelled'` still exits `1`.
      4. Any other skip, failure, or cancellation across the four dependencies causes `merge-reports` to exit `1` (`conclusion: failure`), preventing a broken build or unexpected skip from bypassing required browser checks on PRs/pushes while keeping manual `workflow_dispatch` runs (both on `refs/heads/main` and on other refs) green when `build`, `test`, and `accessibility` succeed.
- **Alternatives considered:**
  - *Rely on `needs: [build]` alone without an `always()` fail-closed required check:* Rejected (`R4B-F1` / `R4B-01`) — GitHub skips downstream jobs when `build` fails, and skipped required checks do not block merging.
  - *Compare `manifest.runAttempt` to the consumer's `GITHUB_RUN_ATTEMPT`:* Rejected (`R4B-F2` / `R4B-02`) — breaks "Re-run failed jobs" when `build` succeeded on attempt 1 and a flaky shard is retried on attempt 2.
  - *Write `.build/build-provenance.json` at the `.build/` root:* Rejected (`R4B-03`) — violates the `.build/{cache,reports,dist}/` umbrella and `build.config.json` SSoT path contract.

### D4: Named postbuild runner (`scripts/postbuild.mjs`) with process isolation and stage timing

Replace the inline `&&` command string in `package.json:40` with `"postbuild": "node scripts/postbuild.mjs"`, where `scripts/postbuild.mjs` exports `POSTBUILD_STAGES` and spawns each stage sequentially in a child process.

- **Why:** Several postbuild scripts mutate process-global state or call `process.exit(1)` directly on error (`scripts/sri.mjs:129`, `scripts/csp.mjs:286`, `scripts/minify-theme-css.mjs:37`, `scripts/sync-build-config.mjs:72`). Spawning each stage as a child process via `spawnSync` preserves complete process isolation, exact exit-code propagation, and working-directory behavior while adding `hrtime.bigint()` per-stage timing (`[postbuild] <name> (<ms>ms)`).
- **Command-body and gate parity:**
  - Every stage executes its full canonical command body. In particular, stage 10 (`lint:design`, defined in `package.json:62` as `"npm run check:oklch-hex-parity && design.md lint DESIGN.md"`) MUST execute both `check:oklch-hex-parity` and `design.md lint DESIGN.md` in order (either by invoking `npm run lint:design` or running both child commands sequentially under the `lint:design` stage), so an OKLCH/hex parity failure halts before `design.md lint` and subsequent stages.
  - `scripts/postbuild.mjs` guards its execution entrypoint behind `path.resolve(process.argv[1] ?? "") === fileURLToPath(import.meta.url)` so importing `POSTBUILD_STAGES` from `tests/lint-readme-postbuild-chain-sync.test.mts` or `tests/postbuild-gates.test.mts` is completely side-effect-free.
  - If a child stage exits with non-zero status `E`, fails to spawn (`error`, e.g., `ENOENT`), or is terminated by a signal (`signal`, e.g., `SIGTERM`), `scripts/postbuild.mjs` immediately stops without running subsequent stages and exits non-zero (`E` or `1`).
  - `POSTBUILD_STAGES` retains canonical `npmCommand` metadata (`"npm run verify:prerequisites"`, `"npm run verify:design-prerequisites"`, `"npm run lint:tokens"`, `"npm run lint:skip-link"`, `"npm run lint:taglines"`, `"npm run lint:design"`, `"npm run lint:design-md-uniqueness"`, `"npm run verify:indexation"`) so `tests/lint-orphan-npm-scripts.test.mts:128,149` continues to pass without orphan exceptions.

### D5: Keep Astro-native CSP, `node:test` → `vitest`, and CSS delivery as non-mutating research spikes with full worktree/index/untracked guards

Scope Item 5 strictly as measurement and prototyping tasks that run in disposable `mkdtempSync` directories outside the repository worktree and write only their declared evidence report under `openspec/changes/modernize-build-pipeline/evidence/`.

- **Why:**
  - **Astro-native CSP (Spike 5A):** Astro 7 includes `injectedCsp` plumbing (`node_modules/astro/dist/core/config/settings.js:125-128`), but upstream docs note limitations with external scripts/styles, and Astro has no native SRI replacement for `scripts/sri.mjs` or the post-write disk re-read audit in `scripts/csp.mjs:218-255`.
  - **`node:test` → `vitest` pilot (Spike 5B):** `vitest.config.ts:3-11` and `docs/agents/testing.md:9-16` enforce disjoint test discovery because loading `vitest` and `@playwright/test` in one process crashes with `Symbol($$jest-matchers-object)`. `tests/visual-palette-threshold.test.mjs` imports Playwright internals and must stay on `node:test`. A single-file pilot in a temp copy measures whether migrating pure unit tests (`tests/oklch-to-hex.test.mjs` or `tests/tweaks-parse.test.mjs` + `tests/tweaks-state.test.mts`) yields meaningful startup savings on Node `22.23.4`.
  - **CSS delivery (Spike 5C):** `public/assets/theme.css` is served at `/assets/theme.css`, minified in-place in `.build/dist/assets/theme.css` by `scripts/minify-theme-css.mjs:14-25`, skipped for content-addressed SRI by `scripts/sri.mjs:101-104`, and listed in the Cloudflare cache-purge manifest (`tests/ci-workflow-behavior.test.mts:329`).
- **Immutability guard (`R4B-F6`):** Plain `git diff` misses staged changes and untracked files. Every spike task MUST verify after completion that `git diff --exit-code`, `git diff --cached --exit-code`, and `git status --porcelain=v1 --untracked-files=all -- src/ public/ scripts/ tests/ rules/ deploy/ docs/ .github/ .agents/ package.json package-lock.json astro.config.ts tsconfig.json vitest.config.ts playwright.config.ts build.config.json build.config.ts lighthouserc.json lychee.toml` are all empty.

## Risks / Trade-offs

- **[Risk] Producer `build` failure or cancellation skips downstream browser jobs and could satisfy branch protection if required checks are skipped, while unconditional four-job enforcement would fail healthy `workflow_dispatch` runs where `visual-regression` intentionally skips (`.github/workflows/playwright.yml:221,275`)** → **Mitigation:** `merge-reports` (`.github/workflows/playwright.yml:171-218`, a required check in `docs/build-artifacts.md:118`) runs with `if: ${{ always() }}` and `needs: [build, test, visual-regression, accessibility]` and enforces an event-aware policy: `build`, `test`, and `accessibility` must equal `'success'` on all events, `visual-regression` must equal `'success'` on `pull_request`/`push` and may be `'skipped'` only on `workflow_dispatch`, and any other skip/failure/cancellation exits `1`.
- **[Risk] "Re-run failed jobs" increments consumer `GITHUB_RUN_ATTEMPT` while keeping the attempt-1 `build` producer** → **Mitigation:** Bind `manifest.producerRunAttempt` to `needs.build.outputs.producer-run-attempt` (`EXPECTED_PRODUCER_RUN_ATTEMPT`) rather than the consumer's `GITHUB_RUN_ATTEMPT`; document that retries after the 1-day artifact retention window require "Re-run all jobs".
